3.1 No passo a passo, o que cresce na recursão comum e não cresce na recursão em cauda? Por quê?
Na recursão comum as chamadas ficam pendentes na pilha de execução pois ainda há operações para realizar quando cada chamada terminar. Na recursão em cauda, a chamada recursiva é a última operação da função.
3.2 Por que o Scheme fez um milhão de chamadas e o Python parou com RecursionError? (Dica: releia o quadro sobre a otimização da chamada em cauda e a mensagem de erro do Python. O livro fala do Scheme na p. 656.)
O scheme suporta a otimização de chamadas em cauda, conforme a linguagem exige. Porém Python não otimiza de forma direta as chamadas em cauda.

5.1 Como o Haskell consegue imprimir parte de uma lista infinita? E por que primeiro 42 (div 1 0) não deu erro de divisão por zero?
O Haskell usa avaliação preguiçosa, só calcula quando necessário, take 5 squares calcula apenas os cinco primeiros quadrados, primeiro 42 (div 1 0) devolve 42 porque a função primeiro, ignorando o segundo argumento.
5.2 O que aconteceu com member 17 squares? Por que ele nunca termina, enquanto member 16 squares terminou? Como você corrigiria? (Dica: squares está em ordem crescente. Quando já dá para desistir da busca? O livro mostra uma solução na p. 670.)
A lista squares contém os quadrados dos números naturais em ordem crescente, member 17 squares nunca termina porque 17 não é um quadrado perfeito. Pensei em parar a procura quando o elemento atual for maior do que o valor procurado.

Prática 7: O laço vira pipeline

7.1 Primeiro exercício escolhido (1, 2 ou 3): cole o seu código reescrito.
Java 1
import java.util.*;

public class Main {
    public static void main(String[] args) {
        List<Integer> nums = List.of(3, 8, 5, 12, 7, 6);

        int soma = nums.stream()
            .filter(n -> n % 2 == 0)
            .mapToInt(n -> n * n)
            .sum();

        System.out.println(soma);
    }
}

8.3 Qual é o erro de impressão, e como corrigir? O que a mensagem do compilador diz sobre o tipo que ele inferiu?
O erro de impressão está em b <- h, que deveria ser b <= h, o correto é <=, pois queremos selecionar os elementos menores ou iguais a 'h'. A mensagem do compilador indica que ele inferiu tipos incompatíveis.
